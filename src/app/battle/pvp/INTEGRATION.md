# PvP 3 vs 3 (NEAR testnet)

## Runtime

- Lobby: `/battle/pvp`, linked from Find Match. Players choose a unique lowercase username, three owned eligible NFTs, and one of those team cards as their stake. Search the waiting rooms by username or room code; the other player chooses their own team/stake and explicitly locks it. This is an open-room/invite lobby, not ranked matchmaking.
- `create_pvp` and `join_pvp` transfer each stake into game-contract custody and lock the remaining team cards. Market cannot sell or list them; Daily Boss eligibility also excludes locked team cards. Reserved collection slots guarantee settlement/refund can return both NFTs. One active room per wallet; up to 64 simultaneous rooms.
- A browser-generated Ed25519 session public key is authorized in each escrow transaction. It only authorizes actions for that player's room. The private session key stays in that browser's local storage, never on the server or chain. Clearing browser storage loses that action session; the wallet can still cancel an unjoined room or recover escrow at contract expiry.
- The existing wallet identity remains authoritative. Usernames are labels uniquely reserved by the wallet on-chain. They are not passwords or a replacement for signing escrow/claim transactions. The UI shows usernames rather than wallet addresses.
- Actions and 1.5-second heartbeats use the Vercel Node route `/api/pvp/room`, backed by Neon Postgres in Singapore. The DB transaction locks one room row with SELECT FOR UPDATE. Both signed choices resolve from the same round snapshot; the first submission has no turn advantage. Opponent choices are hidden until both submit. One strike/team/round; scanMon runtime stats are 120 HP each, Pikachu 45 strike and others 35. Printed art stats are unchanged.
- No action transaction is sent on-chain. The backend computes a deterministic winner and signs a short-lived proof with the configured server-only referee key. This is a trusted referee architecture, not a trustless decentralized PvP validator. Never expose its private key to the browser. Contracts verify domain, room, deadline, participant, winner, signature and terminal state before settlement. The configured referee is currently the existing dedicated testnet sponsor's Ed25519 key.
- The winning wallet claims its own stake back plus the one losing stake. This is a transfer of existing NFTs, not a new mint. Claims are idempotent. Draws and a heartbeat disconnect lasting over 90 seconds produce a refund certificate; either participant may submit it and return both stakes. Intentional disconnect also refunds by the user's chosen policy. There is no unilateral active-match cancel before that proof. A participant can still delay submission while remaining connected; the hard 24-hour recovery deadline is the fallback.
- A 24-hour on-chain deadline allows escrow recovery even with the backend/database/session offline. An open unjoined room can be cancelled by its creator sooner. There is no guaranteed background refund transaction: a player submits the refund/cancel/recovery transaction using their wallet.
- Lock animation appears after escrow confirmation. Victory uses an unlock animation followed by the existing starfall, peel and split-card reveal, displaying the opponent's actual staked card and a Claim staked card button. Ownership changes only after finality and refreshes the shared vault used by Collection, Market and Battle. Scan code is unchanged.

## Operations

Neon project: `misty-scene-05254725`, region `aws-ap-southeast-1`. `PVP_DATABASE_URL` is a server-only pooled connection secret, configured locally and in Vercel Production/Preview; it must never be NEXT_PUBLIC. Schema: `scripts/pvp-schema.sql`. Vercel handles short HTTP requests; no persistent WebSocket process or process-local room map is required.

Build/test the WASM, then `node scripts/deploy-pvp.mjs` upgrades only the existing testnet game and configures the referee public key. The existing persisted Game schema is unchanged; PvP uses separately prefixed maps. Deployments are recorded in `smartcontract/deployments/pvp-upgrade.json`.

`npm exec tsx -- scripts/test-pvp.ts` uses the dedicated QA Alice/Bob wallets to exercise the deployed contract plus backend HTTP endpoint. It checks actual escrow custody, invalid signatures/foreign actors, concurrent round resolution, settlement/retry, and disconnect refund. `PVP_TEST_URL` selects a deployed API. It uses real testnet transactions and temporarily ages only its own QA room's heartbeat in SQL to test the 90-second branch. Do not run this script against user wallets or mainnet. Public receipts are in `pvp-validation.json`; no signing keys are recorded.
